# 06 — Testing, CI & Release Engineering

## Context

Shoo is a native macOS menu-bar app (Swift + SwiftUI + Apple Vision, on-device, macOS 14+) distributed via the Mac App Store. The Xcode project is generated by XcodeGen from `project.yml`; `Shoo.xcodeproj` is committed alongside it. Today the build/test loop is:

```sh
bash scripts/bootstrap.sh        # installs xcodegen, runs `xcodegen generate`
xcodebuild -project Shoo.xcodeproj -scheme Shoo -destination 'platform=macOS' build
xcodebuild -project Shoo.xcodeproj -scheme Shoo -destination 'platform=macOS' test
```

There is exactly one test target (`ShooTests`) with one test file (`ShooTests/ProximityAnalyzerTests.swift`, 5 XCTest cases over the pure overlap logic). A `.swiftlint.yml` exists but SwiftLint is not installed and is not wired into the build or any CI. There is no CI, no coverage measurement, no release automation, and no `Makefile`.

This plan owns the **testing strategy, the CI pipeline, coverage measurement, developer ergonomics, and release-automation wiring**. It does **not** own signing identities, provisioning profiles, App Store Connect metadata, or notarization mechanics — those belong to plan 05 (App Store distribution). This plan builds the automation seams (fastlane lanes, tag-triggered workflow) into which plan 05 drops the signing/submission specifics.

The codebase is deliberately structured for testability. The key seams already present:

- `Shoo/Detection/ProximityAnalyzer.swift` — a pure `struct`, no Vision/AVFoundation imports. Already the most-tested piece.
- `Shoo/Alerting/AlertManager.swift` — `@MainActor` class holding debounce (`requiredSustainedHits`) and cooldown (`cooldown` arg) state. Testable, but currently hard-wires `OverlayWindow()` and reads `Date()` directly (no clock seam).
- `Shoo/Models/AppSettings.swift` — `UserDefaults`-backed `ObservableObject`; `init(defaults:)` already accepts an injectable `UserDefaults`, so a `UserDefaults(suiteName:)` test instance works.
- `Shoo/Camera/CameraManager.swift` — concrete class, no protocol seam yet; emits frames via `onFrame: ((CVPixelBuffer) -> Void)?`.
- `Shoo/Detection/HandFaceDetector.swift` — owns the Vision requests and an `analyzer`; `process(_:completion:)` is the integration entry point.

## Goals / Definition of done

- A test pyramid is defined and partially implemented: expanded pure unit tests, a mock frame/camera seam enabling deterministic detection tests from fixtures, and lightweight overlay/settings UI tests where they don't introduce flake.
- A protocol seam (`FrameSource`) decouples the pipeline from `AVCaptureSession` so tests can drive frames from recorded fixtures with no hardware.
- A clock seam decouples `AlertManager` cooldown from wall-clock `Date()` so cooldown tests are deterministic and fast.
- SwiftLint runs locally and gates in CI (lint failures fail the build).
- A GitHub Actions workflow on a macOS runner: installs XcodeGen, generates the project, builds, runs tests with code coverage, runs SwiftLint, verifies XcodeGen has no uncommitted drift, and surfaces a coverage number. Codesigning is disabled for CI (`CODE_SIGNING_ALLOWED=NO`).
- Coverage is measured via `xcodebuild -enableCodeCoverage YES` + `xccov`, with a documented (initially non-blocking) threshold on the pure-logic layer.
- Release automation is wired: a `fastlane` setup with `gym`/`deliver`/`snapshot` lanes (signing/upload params handed to plan 05), a build-number bump strategy, and a tag-triggered release workflow.
- A `Makefile` gives `make bootstrap`, `make build`, `make test`, `make lint`, `make coverage`, `make ci` mirroring CI locally.
- `decisions` documented inline: **XCTest** is the framework of record (see Design); fixtures live under `ShooTests/Fixtures/`.

Done = an engineer can run `make ci` locally and push a PR that is gated by the CI workflow, and `git tag vX.Y.Z && git push --tags` kicks off the (skip-signing-until-05) release lane.

## Design

### Test pyramid

```
            ┌───────────────────────────────┐
            │  UI / snapshot  (few, gated    │   OverlayView render, SettingsView
            │  loosely, allowed to be skipped │   binding round-trips
            │  in CI if flaky)               │
            ├───────────────────────────────┤
            │  Integration (mock FrameSource)│   recorded fixtures → HandFaceDetector
            │                                 │   → ProximityAnalyzer → AlertManager
            ├───────────────────────────────┤
            │  Pure unit  (many, fast,        │   ProximityAnalyzer, AlertManager
            │  deterministic, the bulk)       │   state machine, AppSettings, mapping
            └───────────────────────────────┘
```

#### Framework decision: XCTest (not Swift Testing)

Swift Testing requires Xcode 16 / Swift 6 toolchain and the `Testing` module. The deployment floor here is macOS 14, and the existing test target and `project.yml` (`SWIFT_VERSION: "5.0"`) are XCTest-based. **Decision: standardize on XCTest** for this plan to avoid a toolchain bump mid-stream and to keep CI matrix simple. Swift Testing can be adopted later (it coexists with XCTest in the same target) once the project moves to Swift 6 — call that out as a follow-up, not a blocker. All new tests in this plan are XCTest.

#### Layer 1 — pure unit tests (expand)

- **`ProximityAnalyzerTests`** (exists): add boundary cases — point exactly on the (unexpanded) edge, `minPointsInside` of 1 and 3, negative/zero margin, points at normalized extremes (0,0)/(1,1), face box touching image edge. Add a parameterized helper to sweep margins.
- **`AlertManagerTests`** (new): exercise the debounce/cooldown state machine. This requires two seams (below): inject a `Clock` and an `OverlayPresenting` so we assert "fired N times" without real windows and without `sleep`.
  - resets `consecutiveHits` on a negative frame.
  - fires only after `requiredSustainedHits` consecutive positives.
  - does not refire within `cooldown`; refires after cooldown elapses (advance the injected clock).
  - cooldown read fresh each call (change cooldown mid-stream).
- **`AppSettingsTests`** (new): persistence + defaults + migration.
  - register-defaults values surface on a fresh suite.
  - writing a `@Published` property persists to the injected `UserDefaults`.
  - a new instance over the same suite reads the persisted value.
  - **migration**: a `schemaVersion` key + a `migrate()` step (see Implementation) — test that legacy stored values (e.g. an old `cooldown` key in ms, or out-of-range sensitivity) are migrated/clamped on init.
- **`SensitivityMappingTests`** (new): the `sensitivity (0…1) → ProximityAnalyzer.margin` mapping. This mapping currently lives implicitly (settings comment says "mapped to margin"); this plan extracts it into a pure free function `marginForSensitivity(_:) -> CGFloat` (in `Shoo/Detection/`) and tests endpoints + monotonicity (higher sensitivity ⇒ larger margin ⇒ triggers earlier) + clamping of out-of-range input.

#### Layer 2 — mock FrameSource seam + integration tests

Introduce a protocol so the pipeline can be fed by a fixture player instead of `AVCaptureSession`:

```swift
// Shoo/Camera/FrameSource.swift
import CoreVideo

protocol FrameSource: AnyObject {
    var onFrame: ((CVPixelBuffer) -> Void)? { get set }
    func start()
    func stop()
}
```

- `CameraManager` is made to conform (`final class CameraManager: NSObject, FrameSource` — it already has `onFrame`, `start()`, `stop()`).
- `AppState` holds `private let camera: FrameSource` instead of the concrete type, injected via `init(camera: FrameSource = CameraManager(), …)`.
- In tests, a `MockFrameSource` (in `ShooTests/Support/`) lets a test push specific `CVPixelBuffer`s on demand:

```swift
// ShooTests/Support/MockFrameSource.swift
final class MockFrameSource: FrameSource {
    var onFrame: ((CVPixelBuffer) -> Void)?
    func start() {}
    func stop() {}
    func emit(_ buffer: CVPixelBuffer) { onFrame?(buffer) }
}
```

Two integration test styles:

1. **Geometry-level integration (preferred, no real Vision dependency):** feed recorded *landmark fixtures* (face `CGRect` + hand `[CGPoint]`) straight into `ProximityAnalyzer` and `AlertManager` to assert end-to-end "frames → fire/no-fire" sequences. Fully deterministic, no images, no GPU. This is the bulk of integration coverage.
2. **Vision-level integration (optional, opt-in, may be CI-skipped):** feed recorded *sample frames* (small PNG/JPEG fixtures of a hand near a face) into `HandFaceDetector.process(_:completion:)` and assert the boolean. Vision model output can vary across OS/Xcode versions, so these tests assert *loose* expectations (e.g. "a clear hand-on-face frame yields true at least once across the sequence") and are tagged so CI can skip them via an env flag (`SHOO_SKIP_VISION_TESTS=1`) if they prove flaky on the runner image.

#### Clock + presenter seam for AlertManager

`AlertManager` currently reads `Date()` and constructs `OverlayWindow()` directly. Add two minimal seams (kept private-by-default so production call sites are unchanged):

```swift
// Shoo/Support/Clock.swift
protocol Clock { func now() -> Date }
struct SystemClock: Clock { func now() -> Date { Date() } }

// In AlertManager: a presenter protocol so tests can count fires without windows.
@MainActor protocol OverlayPresenting { func show() }
extension OverlayWindow: OverlayPresenting {}
```

`AlertManager.init(presenter: OverlayPresenting = OverlayWindow(), clock: Clock = SystemClock(), requiredSustainedHits: Int = 3)`. Tests inject a `FakeClock` (mutable `now`) and a `SpyPresenter` (increments a counter). No production behavior changes.

#### Layer 3 — UI / snapshot tests (lightweight, defensive)

- **No third-party snapshot SPM dependency by default.** Mac App Store + on-device + minimal-deps ethos argues against pulling `swift-snapshot-testing`. Instead:
  - **Overlay render smoke test:** an `XCTestCase` that hosts `OverlayView` in an `NSHostingView`, forces layout (`layoutSubtreeIfNeeded`), and asserts it produces a non-empty bitmap of the expected size. This catches "view fails to build/layout" without pixel-diffing.
  - **Settings binding round-trip:** a logic test (not a driven UI test) that mutates `AppSettings` and asserts the persisted value — the `SettingsForm` binds directly to `AppSettings`, so the binding correctness is covered by `AppSettingsTests`. We do **not** add an `XCUITest` target (XCUITest on a menu-bar/`MenuBarExtra` app is brittle and slow; not worth the flake).
  - If pixel-accurate snapshots are later desired, add `pointfreeco/swift-snapshot-testing` to `ShooTests` only via SwiftPM in `project.yml` (`packages:` + per-target `dependencies:`), record on a pinned Xcode, and mark snapshot tests CI-skippable. Documented as optional follow-up, not in initial scope.

### Linting / formatting

- **SwiftLint** is the gate. Install locally with `brew install swiftlint`. Config already exists (`.swiftlint.yml`).
- Run: `swiftlint lint --strict` (treats warnings as errors for CI gating) from repo root; it picks up `included:` (`Shoo`, `ShooTests`).
- **Do not** add SwiftLint as an Xcode build phase (keeps the XcodeGen-generated project clean and avoids requiring the tool for local app builds). Lint runs via `make lint` and CI only.
- **swift-format (optional):** add `.swift-format` config and a `make format` target running `swift format` (the Apple `swift-format`, bundled with the Swift 5.9+ toolchain as `swift format`). Keep it *format-only*, not a CI gate initially, to avoid double-tooling churn with SwiftLint's autocorrect.
- **Pre-commit hook (optional, opt-in):** a `scripts/install-git-hooks.sh` that symlinks a `pre-commit` running `swiftlint lint --strict --quiet` on staged Swift files. Opt-in (developers run the installer); not forced, since hooks can't be committed-as-active.

### CI architecture

Single workflow `.github/workflows/ci.yml`, triggered on `push` to `main`/`master` and on `pull_request`. One job `build-test` on a macOS runner. Steps: checkout → select Xcode → install tools (XcodeGen, SwiftLint via Homebrew, cached) → generate project → **verify no XcodeGen drift** → lint → build (no signing) → test with coverage → extract & print coverage → upload result bundle artifact.

Xcode-version pin: use `maxim-lobanov/setup-xcode@v1` with an explicit version to keep Vision behavior stable. Runner image `macos-14` (matches the macOS 14 floor and has Xcode 16.x). A small matrix can pin both `macos-14`/Xcode 16.2 now and add `macos-15`/newer later; start single-entry to keep runtime/cost down.

```yaml
# .github/workflows/ci.yml
name: CI

on:
  push:
    branches: [main, master]
  pull_request:

concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true

jobs:
  build-test:
    name: Build & Test
    runs-on: macos-14
    env:
      SCHEME: Shoo
      PROJECT: Shoo.xcodeproj
    steps:
      - uses: actions/checkout@v4

      - name: Select Xcode
        uses: maxim-lobanov/setup-xcode@v1
        with:
          xcode-version: '16.2'

      - name: Cache Homebrew downloads
        uses: actions/cache@v4
        with:
          path: ~/Library/Caches/Homebrew
          key: brew-${{ runner.os }}-xcodegen-swiftlint

      - name: Install tools
        run: |
          brew install xcodegen swiftlint

      - name: Generate Xcode project
        run: xcodegen generate

      - name: Verify XcodeGen has no drift
        run: |
          # The committed .xcodeproj must match what project.yml generates.
          if ! git diff --quiet -- Shoo.xcodeproj; then
            echo "::error::Shoo.xcodeproj is out of sync with project.yml. Run 'xcodegen generate' and commit."
            git diff --stat -- Shoo.xcodeproj
            exit 1
          fi

      - name: SwiftLint
        run: swiftlint lint --strict --reporter github-actions-logging

      - name: Build (no signing)
        run: |
          set -o pipefail
          xcodebuild \
            -project "$PROJECT" -scheme "$SCHEME" \
            -destination 'platform=macOS' \
            -configuration Debug \
            CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO CODE_SIGN_IDENTITY="" \
            build | xcbeautify

      - name: Test with coverage
        run: |
          set -o pipefail
          xcodebuild \
            -project "$PROJECT" -scheme "$SCHEME" \
            -destination 'platform=macOS' \
            -configuration Debug \
            -enableCodeCoverage YES \
            -resultBundlePath TestResults.xcresult \
            CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO CODE_SIGN_IDENTITY="" \
            test | xcbeautify

      - name: Report coverage
        run: bash scripts/coverage.sh TestResults.xcresult

      - name: Upload result bundle
        if: ${{ always() }}
        uses: actions/upload-artifact@v4
        with:
          name: TestResults
          path: TestResults.xcresult
          retention-days: 7
```

`xcbeautify` (installed alongside, `brew install xcbeautify`) is cosmetic; if omitted, drop the pipe. Note `git diff` for drift requires checking the committed `.xcodeproj` in; the repo does commit it.

### Coverage measurement

`scripts/coverage.sh` parses the `.xcresult` with `xccov` and enforces a per-target floor on the pure-logic layer:

```sh
#!/usr/bin/env bash
# scripts/coverage.sh <result-bundle.xcresult>
# Prints overall + per-target coverage and (optionally) gates on a floor.
set -euo pipefail
BUNDLE="${1:-TestResults.xcresult}"
FLOOR_PURE="${COVERAGE_FLOOR_PURE:-0}"   # set to e.g. 85 once the suite is mature

echo "== Coverage report ($BUNDLE) =="
xcrun xccov view --report --only-targets "$BUNDLE"

# Extract Shoo.app line coverage as a percentage for the summary line / badge.
PCT=$(xcrun xccov view --report --json "$BUNDLE" \
  | python3 -c 'import json,sys; d=json.load(sys.stdin); \
t=[x for x in d["targets"] if x["name"].startswith("Shoo.app")]; \
print(round((t[0]["lineCoverage"] if t else 0)*100,1))')
echo "Shoo.app line coverage: ${PCT}%"

if (( $(echo "$PCT < $FLOOR_PURE" | bc -l) )); then
  echo "::error::Coverage ${PCT}% is below floor ${FLOOR_PURE}%"
  exit 1
fi
```

- Threshold strategy: **start non-blocking** (`COVERAGE_FLOOR_PURE=0`) to land CI, then ratchet. Target: the pure-logic files (`ProximityAnalyzer`, `AlertManager`, `AppSettings`, sensitivity mapping) at **≥ 85% line coverage**; whole-app number reported but not gated (camera/Vision/overlay are hardware/UI and can't be fully covered headlessly).
- Optionally surface coverage on PRs by parsing the `%` into the GitHub job summary (`echo "..." >> "$GITHUB_STEP_SUMMARY"`) or via Codecov (`codecov/codecov-action@v4` consuming an `xccov`→cobertura conversion); Codecov is optional and noted for plan-future, since it adds an external dependency/token.

```makefile
	bash scripts/install-git-hooks.sh

	rm -rf TestResults.xcresult build DerivedData
```

### Release automation (wiring only; signing/submission → plan 05)

- **fastlane** under `fastlane/` with `Fastfile`, `Appfile`, `Matchfile`/`Gymfile` stubs. Lanes:
  - `lane :tests` — runs `scan` (xcodebuild test wrapper) with coverage; usable from CI as an alternative to raw `xcodebuild`.
  - `lane :build_unsigned` — `gym` with `skip_codesigning: true` for CI archive smoke checks.
  - `lane :bump` — bumps `CURRENT_PROJECT_VERSION` (build number) and optionally `MARKETING_VERSION`; since versions live in `project.yml` (`settings.base`), the bump edits `project.yml` (via `yq` or a small Ruby helper) then runs `xcodegen generate` and commits. **Decision: version source of truth = `project.yml`**, not `agvtool`, because the project is generated.
  - `lane :release` — archive + `deliver`/`upload_to_app_store` (TestFlight/App Store). **Signing identity, `app_identifier`, API key (`app_store_connect_api_key`), and metadata are placeholders here and filled in by plan 05.**
  - `lane :screenshots` — `snapshot` wiring for App Store screenshots (also plan-05-owned content; this plan provides the lane skeleton).
- **Build-number strategy:** monotonic integer in `CURRENT_PROJECT_VERSION`. CI release lane sets it from the run (e.g. `git rev-list --count HEAD` or a date-based number) so every uploaded build is unique; `MARKETING_VERSION` is bumped manually via `make`/`fastlane bump` per release.
- **Tagging / release workflow** `.github/workflows/release.yml`, triggered on `push` of tags matching `v*.*.*`:

```yaml
# .github/workflows/release.yml
name: Release
on:
  push:
    tags: ['v*.*.*']
jobs:
  archive:
    runs-on: macos-14
    steps:
      - uses: actions/checkout@v4
      - uses: maxim-lobanov/setup-xcode@v1
        with: { xcode-version: '16.2' }
      - run: brew install xcodegen
      - run: xcodegen generate
      # Plan 05 fills in signing (match/API key) + `fastlane release`.
      # Until then this lane only produces an unsigned archive to prove the path.
      - run: bundle exec fastlane build_unsigned
```

The release workflow intentionally stops at an unsigned archive until plan 05 provides secrets (`APP_STORE_CONNECT_API_KEY`, signing cert) via GitHub Actions encrypted secrets.

## Edge cases & risks

- **XcodeGen drift between `project.yml` and committed `.xcodeproj`.** The CI drift check (`git diff --quiet -- Shoo.xcodeproj` after `xcodegen generate`) catches it, but XcodeGen output can differ across XcodeGen *versions* (object ordering, UUIDs). Mitigate by pinning the XcodeGen version in CI (`brew install xcodegen` installs latest — prefer `brew install xcodegen` then assert `xcodegen --version`, or install a pinned formula/bottle) and committing with the same version locally. If drift is purely cosmetic/UUID churn, downgrade the check from hard-fail to a warning, or stop committing the `.xcodeproj` (the `.gitignore` has a commented line to ignore it) — but that's a project-policy change, flag to maintainers.
- **CI signing.** Build/test must pass `CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO CODE_SIGN_IDENTITY=""`. `ENABLE_HARDENED_RUNTIME: YES` in `project.yml` is fine for unsigned debug build/test. The release/archive path *does* need signing — deferred to plan 05; the release workflow stops at an unsigned archive until then.
- **Flaky Vision-level tests.** `VNDetectHumanHandPoseRequest`/`VNDetectFaceRectanglesRequest` output varies by OS/Xcode/hardware and the GitHub macOS runner has no GPU-accelerated camera path; results on sample images may differ from a dev Mac. Mitigation: keep Vision-level tests *opt-in* and *loose-assertion*, gate behind `SHOO_SKIP_VISION_TESTS`, and make the geometry-level (landmark-fixture) integration tests the deterministic backbone.
- **UI/snapshot flake.** Pixel snapshots break on macOS point-release rendering changes and font/material differences across runner images. Mitigation: no pixel-diffing in initial scope; only a "renders to non-empty bitmap of expected size" smoke test. No `XCUITest` target for the menu-bar app.
- **`AlertManager` is `@MainActor`.** Tests must run on the main actor (`@MainActor final class AlertManagerTests`). `FakeClock`/`SpyPresenter` are `@MainActor` where needed.
- **Coverage of camera/overlay layers is inherently low** (hardware/windowing). Don't gate whole-app coverage; gate only the pure-logic floor to avoid a perpetually red bar.
- **Homebrew install time on CI** (xcodegen/swiftlint) adds ~1–2 min. Cache `~/Library/Caches/Homebrew`; these are already-bottled formulae so installs are fast.
- **Fixture bundling.** JSON fixtures must actually ship in the `ShooTests` bundle (`Bundle(for:).url(forResource:withExtension:)`). Verify XcodeGen copies `ShooTests/Fixtures/*.json` as resources; if not, add an explicit `resources:` entry or a `buildPhase: resources` in `project.yml`.
- **`AppSettings` migration ordering.** `migrate()` must run before `@Published` values are read in `init`, and must not re-trigger the `didSet` writes in a way that corrupts the suite. Set raw `defaults` values in `migrate()`, then assign the `@Published` stored properties.
