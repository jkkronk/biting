# 05 — App Store Distribution & Compliance

## Context

Shoo is a macOS menu-bar utility (LSUIElement agent, no dock icon) that watches the
webcam and shows a centered "Stop!" overlay when the user brings hands to their face.
It is native Swift + SwiftUI + Apple Vision, **100% on-device**, with **no network**.
Target is macOS 14+. The chosen distribution channel is the **Mac App Store**
(sandboxed), which is the most demanding path for a camera app: it requires App Sandbox,
a Required Reason privacy manifest, full App Store Connect metadata, and App Review —
where camera apps are scrutinized under privacy guidelines 5.1.1/5.1.2 and 2.5.x.

The project is generated by XcodeGen from `project.yml` → `Shoo.xcodeproj` and built/tested
with `xcodebuild`. The current spec has `DEVELOPMENT_TEAM` empty, `CODE_SIGN_STYLE Automatic`,
`ENABLE_HARDENED_RUNTIME YES`, bundle id `com.shoo.Shoo`, version `0.1.0` / build `1`.

This plan owns everything between "the app builds and runs locally" and "a customer
installs Shoo from the Mac App Store": signing/provisioning wiring, sandbox/entitlements
review, the app icon pipeline, the privacy manifest, the App Store Connect listing,
camera-review-risk mitigation, and the archive/upload/TestFlight/release process.

This plan does **not** implement detection, camera, overlay, or settings — those are
plans 01–04. It assumes the app is feature-complete and stable enough to ship a 1.0.

### Sources verified (2025/2026)

- Required Reason APIs / privacy manifest: Apple TN3183. `UserDefaults` access uses category
  `NSPrivacyAccessedAPICategoryUserDefaults`, reason `CA92.1` ("read/write app-specific
  configuration and state"). Apps that don't declare Required Reason API use have been
  rejected/blocked at App Store Connect submission since May 1 2024.
  <https://developer.apple.com/documentation/technotes/tn3183-adding-required-reason-api-entries-to-your-privacy-manifest>
- macOS screenshots: minimum **1280×800** (16:10), larger sizes such as **2560×1600** /
  2880×1800 accepted at same aspect ratio; 1–10 images, PNG/JPEG, landscape only for previews.
  <https://developer.apple.com/help/app-store-connect/reference/screenshot-specifications/>
- App Review Guidelines 5.1.1: request camera only when the need is obvious from a user
  action, justify the purpose string in-app **and** in Review Notes, and offer limited
  functionality without access where possible.
  <https://developer.apple.com/app-store/review/guidelines/>
- Notarization/upload tooling: `altool` notarization was retired Nov 1 2023 (use `notarytool`);
  `altool` is still valid for **App Store uploads**, but the modern/recommended uploaders are
  **Transporter** and **`xcrun altool --upload-app`** / App Store Connect API. Apple notarizes
  App Store builds server-side, so no client notarization step is needed for the MAS path.
  <https://developer.apple.com/documentation/technotes/tn3147-migrating-to-the-latest-notarization-tool>

## Design

### 1. Signing model

**Local / developer machines — Automatic signing.**
Keep `CODE_SIGN_STYLE = Automatic` and set `DEVELOPMENT_TEAM` to the real Team ID. Xcode
manages the "Apple Distribution" cert and the "Mac App Store" provisioning profile. This is
the lowest-friction path for an individual developer.

**CI — Manual signing.** Automatic signing needs an interactive/authenticated Xcode session
and the developer's keychain, which CI doesn't have. CI must use:
- An **Apple Distribution** certificate (`.p12`) imported into a temporary keychain.
- An explicit **Mac App Store** provisioning profile (`.provisionprofile`) for
  `com.shoo.Shoo`, installed to `~/Library/MobileDevice/Provisioning Profiles/`.
- `exportArchive` with `signingStyle = manual` and `provisioningProfiles` mapping in the
  export options plist.

Because the project is **XcodeGen-generated**, never hand-edit `Shoo.xcodeproj`. All signing
inputs flow through (a) `project.yml` build settings or `xcodebuild` overrides
(`DEVELOPMENT_TEAM=...`, `CODE_SIGN_STYLE=Manual`, `CODE_SIGN_IDENTITY=...`,
`PROVISIONING_PROFILE_SPECIFIER=...`) and (b) the export options plist. The `.xcodeproj`
stays disposable and regenerable.

Two certs/identities are involved for the MAS path: **Apple Distribution** (signs the
`.app`) and **3rd Party Mac Developer Installer / Mac Installer Distribution** (signs the
`.pkg`). Automatic signing creates both; for CI both `.p12`s must be imported.

### 2. Bundle id finalization

`com.shoo.Shoo` is a placeholder. Decide a permanent reverse-DNS id tied to a domain the
team controls (e.g. `ai.synagen.shoo` or `com.<chosen>.Shoo`). It must match the App ID
registered in the Developer portal and the ASC app record, and it can **never** change after
first submission. Once finalized, update `PRODUCT_BUNDLE_IDENTIFIER` and `bundleIdPrefix`
in `project.yml` and the ShooTests id accordingly. **Recommendation:** finalize to
`ai.synagen.Shoo` (owned domain), or keep `com.shoo.Shoo` only if `shoo.com`/`shoo.ai` is
actually owned. This plan uses `com.shoo.Shoo` as a stand-in; substitute the final value
everywhere before the first upload.

### 3. Entitlements & hardened runtime review

The current entitlements are already the minimal correct set for a MAS camera app:

```
com.apple.security.app-sandbox       = true   (required for MAS)
com.apple.security.device.camera     = true   (required to open AVCaptureSession)
```

- **Keep hardened runtime ON** (`ENABLE_HARDENED_RUNTIME = YES`). MAS builds are notarized
  server-side and hardened runtime is expected.
- **Do NOT add** `com.apple.security.network.client/server` — absence reinforces the "no data
  leaves the Mac" privacy claim and is a concrete, reviewer-verifiable signal. The sandbox
  will block any accidental network call, which is a desirable safety net.
- **Do NOT add** any file-access, microphone, location, or hardware entitlements. Shoo reads
  only the camera and writes only `UserDefaults` (which needs no entitlement inside the sandbox).
- **Launch at login** (plan 04) must use `SMAppService` (macOS 13+) / the modern
  ServiceManagement API — it works inside the sandbox **without** a login-item entitlement.
  Do not introduce `com.apple.security.application-groups` or helper-login-item entitlements
  unless plan 04 proves they are required; flag any such addition for re-review here.

Net: **no entitlement changes**. The deliverable is a written confirmation in the PR that the
two-key set is intentional and minimal.

### 4. Privacy manifest (`PrivacyInfo.xcprivacy`)

Add `Shoo/PrivacyInfo.xcprivacy` (bundled as a top-level resource of the `.app`). Contents:

- `NSPrivacyTracking = false`
- `NSPrivacyTrackingDomains = []`
- `NSPrivacyCollectedDataTypes = []` — Shoo collects **nothing**. Camera frames are processed
  transiently in memory and never stored or transmitted, which is not "collection" under
  Apple's definition (consistent with `docs/PRIVACY.md`).
- `NSPrivacyAccessedAPITypes` = one entry:
  - `NSPrivacyAccessedAPIType = NSPrivacyAccessedAPICategoryUserDefaults`
  - `NSPrivacyAccessedAPITypeReasons = ["CA92.1"]` (read/write app's own config/state)

This is the only Required Reason API Shoo uses, assuming plan 04 stores preferences in
`UserDefaults` (sensitivity, cooldown, launch-at-login, watching on/off). If plan 04 instead
uses file-based persistence touching file timestamps, system boot time, disk space, or active
keyboard, add the corresponding category/reason here. **Action item:** confirm with plan 04
which APIs are actually used before finalizing; if `UserDefaults` ends up unused, the
`NSPrivacyAccessedAPITypes` array becomes empty (but keep the file with the tracking/data keys).

XML target (see Files section for the full literal).

### 5. App icon & asset pipeline

The `AppIcon` set needs all 10 PNGs. Pipeline:

1. Design **one 1024×1024 master** (`art/AppIcon-1024.png`, 32-bit RGBA, sRGB, no alpha holes
   for the macOS-rounded-rect look — macOS does **not** auto-mask, so the artwork should sit on
   the standard rounded-square plate with the canonical inset, or be a full-bleed square if a
   custom shape is desired). Keep it on-brand: a stylized open hand / "stop" motif consistent
   with the overlay's "✋ Stop!".
2. Generate the 10 sizes with `sips`/`iconutil` (script in Files section). Required pixel sizes:
   16(@1x), 32(@2x of 16), 32(@1x), 64(@2x of 32), 128(@1x), 256(@2x of 128), 256(@1x),
   512(@2x of 256), 512(@1x), 1024(@2x of 512). Write them into the appiconset and reference
   each from `Contents.json` via a `filename` per slot.
3. **Menu-bar glyph (separate asset).** The status-bar item needs a **template image**
   (monochrome + alpha) so macOS tints it for light/dark menu bars. Add an asset
   `MenuBarIcon` (PDF or 1x/2x PNG, ~18pt) with **"Render As: Template Image"**. Plans 03/04
   consume it via `NSImage(named:)` with `isTemplate = true`. This is *not* the AppIcon.
4. Verify after archive that the built `.app` contains a compiled `Assets.car` with all icon
   sizes; missing sizes cause App Store validation errors at upload.

The 1024 master also doubles as the ASC "App Icon" upload (App Store marketing icon is taken
from the largest icon in the build for macOS, but keep the 1024 master on hand).

### 6. App Store Connect listing plan

- **App name:** "Shoo" (must be globally unique on the App Store; have a fallback like
  "Shoo — Stop Biting" ready in case "Shoo" is taken). Max 30 chars.
- **Subtitle (≤30):** "Stop biting your nails." or "Break the nail-biting habit."
- **Primary category:** **Health & Fitness** (habit/behavior focus). **Secondary:**
  Productivity or Utilities.
- **Promotional text (≤170, updatable without review):** privacy-forward hook, e.g.
  "On-device only. No video ever leaves your Mac."
- **Description (≤4000):** what it does, the on-device/no-network privacy guarantee, how the
  overlay works, menu-bar controls (sensitivity, cooldown, launch at login), macOS 14+ + webcam
  requirement, and an explicit "Shoo never records, stores, or uploads anything."
- **Keywords (≤100, comma-separated):** `nail biting,habit,stop,reminder,focus,webcam,
  privacy,menu bar,bfrb,onychophagia,face touching,productivity` (tune; no spaces wasted).
- **Support URL** and **Marketing URL:** required; point to a project/GitHub/landing page.
- **Privacy Policy URL:** required — host `docs/PRIVACY.md` content at a public URL.
- **Age rating:** complete the questionnaire; expected **4+** (no objectionable content).
- **Pricing:** **Free**, no IAP.
- **Screenshots (macOS):** 1–10, **≥1280×800 16:10** (deliver 2560×1600 retina). Capture the
  real menu-bar dropdown UI and the centered "Stop!" overlay on a desktop. Avoid showing live
  webcam imagery of a real person; use a neutral/staged frame or illustration to keep the
  privacy message clean.
- **App preview (optional):** landscape `.mov`/`.m4v` if desired; not required for launch.
- **Encryption:** set `ITSAppUsesNonExemptEncryption = false` in Info.plist (Shoo uses no
  custom crypto, only OS-provided) to skip the export-compliance prompt each upload.

### 7. Review-risk mitigation (camera scrutiny)

Camera apps draw extra review under **5.1.1 (data collection/permission)**, **5.1.2 (data
use/sharing)**, and **2.5.x (software requirements)**. Mitigations baked into the build +
listing:

- Keep the strong `NSCameraUsageDescription` (already present) — it names the feature and the
  on-device guarantee. Reviewers read the actual on-screen permission prompt.
- Camera is requested only after a clear user action (enabling "watch") — confirm plan 02/04
  gate `AVCaptureDevice` access behind an explicit toggle, satisfying "request only when the
  need is obvious."
- No network entitlement → the privacy claim is structurally enforceable and reviewer-checkable.
- Provide **Reviewer Notes** (full text in Implementation steps) explaining the menu-bar-only
  UI (so the reviewer knows there's no dock icon / main window), how to trigger the overlay,
  and the no-recording/no-network design.
- Because there's no login/account, set "Sign-in required: No" and leave demo credentials blank.

## Implementation steps

> Substitute the finalized bundle id and Team ID everywhere `com.shoo.Shoo` / `<TEAM_ID>` appear.

### A. Developer account & identifiers

1. Confirm/enroll the Apple Developer Program (Organization or Individual). Note the **Team ID**
   (Membership page) — a 10-char string like `AB12CD34EF`.
2. In **Certificates, Identifiers & Profiles → Identifiers**, register an **App ID** with the
   finalized bundle id (`com.shoo.Shoo` placeholder). Capabilities: App Sandbox is implicit for
   Mac; no special capabilities to enable beyond defaults (camera needs none at App ID level).
3. In **App Store Connect → Apps → New App** (platform macOS), create the app record using the
   same bundle id, primary language, and the chosen app name (have the fallback name ready).

### B. Wire signing into the project

4. Edit `project.yml`:
   - `settings.base.DEVELOPMENT_TEAM: "<TEAM_ID>"`
   - Finalize `PRODUCT_BUNDLE_IDENTIFIER` (and `bundleIdPrefix`, ShooTests id) if changing it.
   - Add `settings.base.INFOPLIST_KEY_ITSAppUsesNonExemptEncryption: NO` (or add the key to
     Info.plist directly).
5. `xcodegen generate` and open once in Xcode to let Automatic signing create the
   distribution cert + Mac App Store profile (Signing & Capabilities → confirm no errors).

### C. App icon + menu-bar glyph

6. Add the 1024 master at `art/AppIcon-1024.png`.
7. Add `scripts/make-appicon.sh` (Files section) and run it to populate the appiconset and
   rewrite `Contents.json` with `filename`s.
8. Add `Shoo/Resources/Assets.xcassets/MenuBarIcon.imageset` (template image) for plans 03/04.
9. `xcodegen generate` (assets are already inside `Shoo/`), build, and confirm the icon shows.

### D. Privacy manifest

10. Create `Shoo/PrivacyInfo.xcprivacy` (Files section). XcodeGen already globs `Shoo/`, so it
    is bundled automatically; verify it lands at `Shoo.app/Contents/Resources/PrivacyInfo.xcprivacy`.
11. Reconcile with `docs/PRIVACY.md` (already aligned: None/None/None). Add a one-line note in
    PRIVACY.md that the manifest is the machine-readable mirror of the document.

### E. Local App Store archive

12. Archive (Automatic signing):
    ```sh
    xcodebuild -project Shoo.xcodeproj -scheme Shoo \
      -configuration Release -destination 'generic/platform=macOS' \
      -archivePath build/Shoo.xcarchive archive
    ```
13. Create `ExportOptions-AppStore.plist`:
    ```xml
    <?xml version="1.0" encoding="UTF-8"?>
    <!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
    <plist version="1.0"><dict>
      <key>method</key><string>app-store-connect</string>
      <key>destination</key><string>export</string>
      <key>teamID</key><string><TEAM_ID></string>
      <key>signingStyle</key><string>automatic</string>
      <key>generateAppStoreInformation</key><true/>
    </dict></plist>
    ```
    (On CI use `signingStyle = manual` plus a `provisioningProfiles` dict mapping
    `com.shoo.Shoo` → profile name, and import the Distribution + Installer `.p12`s.)
14. Export the signed `.pkg`:
    ```sh
    xcodebuild -exportArchive -archivePath build/Shoo.xcarchive \
      -exportOptionsPlist ExportOptions-AppStore.plist \
      -exportPath build/export
    ```

### F. Upload & TestFlight

15. Create an App Store Connect **API key** (Users and Access → Integrations → keys; Issuer ID
    + Key ID + `.p8`). Upload:
    ```sh
    xcrun altool --upload-app -f build/export/Shoo.pkg -t macos \
      --apiKey <KEY_ID> --apiIssuer <ISSUER_ID>
    ```
    (Alternative: **Transporter.app**, or `xcrun notarytool`'s sibling tooling / ASC API.
    Apple notarizes App Store builds server-side; no client notarization step.)
16. The build appears in ASC under TestFlight after processing. Add internal testers; install
    via **TestFlight for macOS** (the macOS TestFlight app). Smoke-test camera permission flow,
    overlay, menu-bar controls, launch-at-login.

### G. Listing, review, release

17. Fill the ASC listing per Design §6 (name, subtitle, description, keywords, URLs, category,
    screenshots, age rating, **Free** pricing).
18. **App Privacy → "Get Started" → answer "No, we do not collect data."** (matches the manifest
    and PRIVACY.md). No data types, no tracking.
19. Paste the **Reviewer Notes**:
    > Shoo is a menu-bar-only app (LSUIElement) — there is NO Dock icon and NO main window;
    > all controls live in the macOS menu-bar status item (top-right). It uses the camera ONLY
    > to detect, on-device with Apple's Vision framework, when a hand approaches the face, then
    > shows a brief centered "Stop!" overlay. No video, frames, or derived data are ever
    > recorded, stored, or transmitted — the app has NO network entitlement and runs fully
    > sandboxed with camera-only access. To test: click the menu-bar icon → enable "Watch",
    > grant camera permission when prompted, then raise a hand toward your face to trigger the
    > overlay. No account or sign-in is required.
20. Set encryption answer (handled by Info.plist key), submit for review, and configure
    **Phased Release** (7-day automatic rollout) for 1.0.

## Edge cases & risks

- **Missing icon sizes** → archive/validation failure. Mitigation: generator script + a build
  check that all 10 PNGs exist before archiving.
- **ITMS-91053 Missing API Declaration** if `UserDefaults` (or another Required Reason API from
  plan 04) is used without a manifest entry → upload rejected. Mitigation: ship the manifest;
  re-audit Required Reason APIs whenever plan 04 changes persistence.
- **Camera 5.1.1 rejection** (most likely rejection vector). Mitigations: strong purpose string,
  user-action-gated permission, no network entitlement, explicit Reviewer Notes (Step 19).
- **"App does nothing / can't find UI"** rejection because it's an LSUIElement menu-bar agent —
  reviewers may not find the UI. Mitigation: Reviewer Notes explicitly say "menu-bar only, no
  Dock icon, top-right status item," with exact steps to trigger the overlay.
- **Privacy-label / manifest mismatch** (label says "no data," manifest implies otherwise, or
  vice versa). Mitigation: single source of truth (`docs/PRIVACY.md`) reconciled with both.
- **Bundle id changed after first submission** — impossible to undo. Mitigation: finalize the id
  in this plan **before** the first upload.
- **CI signing brittleness** (Automatic signing can't run headless). Mitigation: dedicated
  manual-signing path with imported certs + explicit profile (coordinate with plan 06).
- **App name "Shoo" already taken.** Mitigation: pre-reserve in ASC early; keep fallback
  "Shoo — Stop Biting".
- **SMAppService login-item edge cases** — if plan 04 needs a helper, it must not silently add
  entitlements that widen the sandbox; route any such change back through this plan's
  entitlements review.
- **Encryption export prompt** every upload if `ITSAppUsesNonExemptEncryption` is unset.
  Mitigation: set it to `false`.
